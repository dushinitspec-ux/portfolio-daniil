<Section id="problem">

The reception desk answers the same questions all day: breakfast hours, the Wi-Fi password,
when the pool opens, how to book a transfer. In a resort hotel in Turkey guests ask them in
Russian, English, Turkish and German, and the staff do not speak all four.

A plain chatbot is risky here. An AI that invents a check-out time or a price causes real
trouble at the desk, and the guest blames the hotel, not the bot.

</Section>

<Section id="solution">

A Telegram bot that answers only from facts the hotel wrote down, and asks a person about
everything else:

- The knowledge base is one Markdown file the hotel edits. `/reload` applies changes without a restart; a broken file keeps the old version.
- The language model (Claude or OpenAI, chosen in the settings) returns **structured JSON** with a `found_in_knowledge_base` flag, so "do I know this?" is a yes/no value, not a guess from the model's wording.
- Unknown questions go to a **staff Telegram group** with an English translation. Staff simply press Reply; the bot translates the answer into the guest's language and shows the original below.
- The guest's language is detected without AI: alphabet, letters such as ı ş ğ or ä ß, and common words. Short messages like "ok" keep the language of the conversation.
- Every failure ends with a person: API down, model refusal or a cut-off answer go to staff; if the staff group cannot be reached, the guest is told to ask at the desk.

</Section>

<Stack />

The whole knowledge base goes into the prompt instead of a vector search: a hotel FAQ is a few
thousand tokens, so retrieval would only add a new way to fail. Because that prompt never
changes between guests, Anthropic caches it and repeated requests cost less. An offline mock
model lets the whole flow run without an API key.

<Section id="bug">

### Guest commands were sent to the AI and to reception as questions

<BugPart id="problem">

Nothing crashed, and the test passed. While writing an end-to-end test for the admin command
`/reload`, I traced what happens when a guest sends it. The bot paid for an AI call, found
nothing in the knowledge base and posted "/reload" to the staff group as a guest question. The
same happened to `/help` or any other command.

</BugPart>

<BugPart id="cause">

aiogram checks handlers in registration order and uses the first one whose filters match. The
admin-only handler correctly ignored the guest, so the message fell through to the catch-all
handler, which treats any text as a question.

</BugPart>

<BugPart id="fix">

A handler for commands in private chats, registered before the catch-all, shows the welcome
text instead. The test now checks both sides: the guest gets the welcome text, and nothing
reaches the staff group. Lesson: a test that only checks "the bad thing did not happen" can
pass for the wrong reason.

</BugPart>
