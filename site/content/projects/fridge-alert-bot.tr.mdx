<Section id="problem">

Gece ısınan bir buzdolabı, sabah bozulmuş yiyecek demektir. Sıcaklık kaydındaki bir boşluk,
hijyen denetiminde sorun demektir. Personel termometrelere günde birkaç kez bakar ve arızaların
çoğunu kaçırır.

Ucuz sıcaklık sensörleri var. Eksik olan, onları izleyip doğru anda bir insanı çağıran şeydir —
hem de biri kapıyı her açtığında boşuna alarm vermeden. Steady Control'de otel ve restoranlardaki
buzdolabı sıcaklık sensörleriyle çalışıyorum; bu yüzden birini ne zaman uyandırmak gerektiğine
karar veren kısmı geliştirdim.

</Section>

<Section id="solution">

Sensörler ölçümleri bir HTTP API'ye gönderir. Küçük bir durum makinesi her ölçümün ne anlama
geldiğine karar verir:

- Uyarı gelmeden önce buzdolabının sınırın üzerinde **5 dakika** kalması gerekir. Bir dakika açık kalan kapı asla uyarı vermez.
- **Her olay için tek uyarı**, ardından süre ve en yüksek sıcaklıkla birlikte "normale döndü" mesajı.
- Normale dönmek için sıcaklığın **sınırın 0,5 °C altına** inmesi gerekir; böylece sınırda gidip gelen bir buzdolabı sohbeti mesaja boğmaz.
- Çevrimdışı kalmış bir sensörden gelen geç veya tekrarlanan ölçümler geçmişe yazılır ama durumu geri almaz. 15 dakikadan eski olaylar kaydedilir ama duyurulmaz.

Telegram'da mutfak ekibi `/status`, `/history <sensor>` (PNG grafik), `/setlimit` ve `/report`
komutlarını kullanır; her sabah günlük özet gelir.

<Section id="code">

Uyarı kuralı saf bir fonksiyondur: veritabanı yok, Telegram yok, sadece "durum + ölçüm → yeni
durum ve belki bir olay". Bu sayede her uç durum üç satırlık bir test olur.

```python
def evaluate(
    current: AlertState,
    *,
    sensor_id: str,
    temperature: float,
    at: datetime,
    limit: float,
    rules: AlertRules,
) -> tuple[AlertState, AlertEvent | None]:
    """Return the next state and, if something worth telling people happened, an event."""
    above = temperature > limit

    if current.state is SensorState.OK:
        if above:
            return AlertState(SensorState.PENDING, at, temperature), None
        return current, None

    started = current.breach_started_at
    peak = (
        temperature
        if current.peak_temperature is None
        else max(current.peak_temperature, temperature)
    )

    if current.state is SensorState.PENDING:
        if not above:
            return AlertState(), None
        if at - started >= rules.delay:
            event = AlertEvent(EventKind.ALERT, sensor_id, temperature, limit, started, peak, at)
            return AlertState(SensorState.ALERT, started, peak), event
        return replace(current, peak_temperature=peak), None

    # ALERT
    if temperature <= limit - rules.hysteresis:
        event = AlertEvent(EventKind.RECOVERED, sensor_id, temperature, limit, started, peak, at)
        return AlertState(), event
    return replace(current, peak_temperature=peak), None
```

<Section id="bug">

### Simülatör sıradan kapı açılmalarında yanlış alarm veriyordu

<BugPart id="problem">

Bir test, simüle edilmiş bir günlük kapı açılmalarını gerçek uyarı kurallarından geçirir. Test
başarısız oldu: tek bir ekipman arızası olmadan 18 uyarı ve normale dönüş mesajı. 30 farklı
rastgele tohumda demo **günde 8,2 yanlış alarm** üretti. Sürekli boşuna alarm veren bir demo,
ürünü bozuk gösterir.

</BugPart>

<BugPart id="cause">

Simülatör açık kapıyı "sensör oda sıcaklığına (24 °C) doğru gider" diye modelliyordu. Bu, çıplak
bir hava sensörünün davranışıdır. Buzdolabının içindeki sensör yiyeceklerin arasında durur ve
karışık havayı ölçer. Arka arkaya iki kapı açılması, ölçümü uyarı gecikmesinden daha uzun süre
5 °C'nin üzerinde tutuyordu.

</BugPart>

<BugPart id="fix">

Artık açık kapı hedefi ayar değerinin birkaç derece üzerine çıkarıyor ve kompresör daha hızlı
toparlıyor. Aynı tohumlarda yanlış alarmlar 8,2'den **günde 0,13'e** düştü. Belirsiz test iki
kesin teste dönüştü: tek bir kapı açılması asla uyarı vermemeli, yoğun bir hafta en fazla iki
uyarı verebilir.

</BugPart>
